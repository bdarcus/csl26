Outward-facing data model + ingest mapping reference for Citum. This is PR 2 of a
two-PR initiative; PR 1 (bean csl26-qtur, merged to main) built the declarative
consts this PR generates docs from. Full context below is self-contained — no
need to read any prior plan file.

## Why

Citum's native data model has no outward-facing documentation, and neither do
the ingest mappings (CSL-JSON, BibLaTeX, native YAML/JSON). `docs/schemas/bib.json`
is complete but machine-only. `docs/reference/BIBLATEX_MAPPING.md` was hand-written
and wrong in several rows (now corrected via generation from PR 1's consts). This
work also produces the coverage/gap matrix that makes bean csl26-11h2's BibLaTeX
modeling decisions legible instead of blind.

## What already landed in PR 1 (main, do not redo)

- `crates/citum-refs/src/formats/biblatex/tables.rs` (new file): `BiblatexBuilder`,
  `BiblatexEntryMapping`, `BIBLATEX_ENTRY_TYPES` const + `BIBLATEX_FALLBACK` row
  (drives entry-type dispatch, behavior-preserving), `BiblatexDataType` enum
  (`Name, Literal, LiteralList, Verbatim, Uri, Integer, Range, Date, Key, Pattern,
  SeparatedValue, EntryKey` -- keyed on BibLaTeX manual sec 2.2.1), `BiblatexFieldMapping`,
  `BIBLATEX_FIELDS` const (46 rows: mapped + `Unmapped` gap list covering every
  item in csl26-11h2 plus `gender` and the `entrykey` fields as `WorkRelation`
  prior art). `note` fields are `Option<&'static str>` (not `""` sentinel).
  Also exports `BiblatexEntryTypeDescriptor`, `BiblatexFieldDescriptor` (serializable
  DTOs) + `biblatex_entry_type_descriptors()`, `biblatex_field_descriptors()`,
  re-exported via `citum_io::biblatex::*`.
- `crates/citum-schema-data/src/reference/conversion/mod.rs`: `CslTypeMapping`
  struct (`csl_type`, `citum_ref_type`, `note: Option<&'static str>`) + `pub const
  CSL_TYPE_MAP` (45 rows), promoted from `contract_tests::EXPECTATIONS` (pure move,
  same assertions). `contract_tests.rs` in the same dir still asserts every CSL
  1.0.2 type round-trips correctly against this const.
- `crates/citum-cli/src/commands/schema.rs`: new `citum schema type-map` output
  (also folded into `schema --out-dir`), emitting `docs/schemas/type-map.json`
  shaped `{ biblatex_entry_types: [...], biblatex_fields: [...], csl_type_map: [...] }`.
  This rides the existing CI schema drift gate (`.github/workflows/ci.yml`'s
  "Verify JSON schemas are up to date" step) automatically -- no CI changes were
  needed for that part.
- `docs/reference/BIBLATEX_MAPPING.md`: currently has a stale-data blockquote
  notice at the top pointing at `type-map.json` as authoritative. **This PR
  replaces the whole file with generated output** (same path, so `docs/reference.html`'s
  existing card link needs no change).

Known corrections `type-map.json` already surfaces (the doc was wrong, the code
wasn't): `@collection`/`@mvcollection`/`@proceedings`/`@mvproceedings` all resolve
to `monograph`/`book`, not `Collection`; `@periodical`/`@reference`/`@inreference`
resolve to the `*` fallback (`monograph`/`document`), not `Serial`/`Collection`.
These are the correct-per-code values; whether the *code* should change to match
original intent is what csl26-11h2 decides, not this PR.

## Deliverables (this PR)

Everything lands under `docs/reference/`. Generated files go in
`docs/reference/generated/` with a
`<!-- GENERATED by scripts/build-data-model-reference.js — do not edit -->`
header; hand-written files stay at the `docs/reference/` top level. Status:
**descriptive reference**, not a normative spec -- no stability promise beyond
existing `docs/reference/SCHEMA_VERSIONING.md` rules.

1. **`docs/reference/DATA_MODEL.md`** (hand-written narrative). Concepts only,
   no field tables (those are generated -- link to them). Sections:
   - Ingest architecture: BibLaTeX maps natively to `InputReference`; CSL-JSON
     *and* RIS both hop through `csl_legacy::csl_json::Reference` first (RIS
     mapping docs are explicitly deferred -- see follow-ups). Small diagram.
   - Reference classes: the five structural classes (`Monograph`, `Collection`,
     `CollectionComponent`, `Serial`, `SerialComponent`) vs the flat legal/
     specialized classes (`Patent`, `Dataset`, `Statute`, etc.), and why both
     exist. Source: `crates/citum-schema-data/src/reference/classes.rs`;
     `docs/specs/TYPE_SYSTEM_ARCHITECTURE.md` (still `Status: Draft` -- see
     follow-ups).
   - The `class` discriminator -> `docs/specs/INPUT_REFERENCE_CLASS_DISCRIMINATOR.md`.
   - Containers: `WorkRelation::Embedded` vs `::Id` -> `docs/specs/GENERALIZED_RELATIONAL_CONTAINER_MODEL.md`.
     Include the biblatex `crossref`/`xdata`/`related` prior-art comparison
     (already written up in `BIBLATEX_FIELDS`' entrykey rows in tables.rs).
   - Contributors: `Contributor`/`ContributorList`/`ContributorEntry`/`ContributorRole`;
     the `author`/`editor`/`translator` shorthands vs the canonical `contributors`
     vec, and why `normalize_contributors()` exists (bean csl26-7ab8).
   - Dates (`DateValue`/EDTF, -> `docs/specs/DATE_MODEL.md`), Titles (`Title::Single`
     vs `::Structured`+`Subtitle`), Rich text (Djot -> `docs/specs/DJOT_RICH_TEXT.md`),
     Forward compatibility (`unknown_fields`/SoftDegrade -> `docs/specs/FORWARD_COMPATIBILITY.md`).
   - Prior art: BibLaTeX sec 2.2.1 -- short table grounding Citum's scalar types
     (`RichText`, `NumOrStr`, `Numbering`, `DateValue`, `Contributor`, `LangID`)
     against biblatex's datatype vocabulary.
   Add to the `PAGES` array in `scripts/build-doc-pages.js` (same treatment as
   `docs/policies/TYPE_ADDITION_POLICY.md`).

2. **`docs/reference/generated/DATA_MODEL_FIELDS.md`** (generated). New generator
   `scripts/build-data-model-reference.js` reads `docs/schemas/bib.json` (already
   generated, already CI-drift-gated -- no Rust changes needed for this part).
   One section per reference class with a field table (field, wire name, type,
   required, description -- descriptions straight from Rust `///` comments via
   schemars), plus a section per closed vocabulary (`MonographType`, `SerialType`,
   `CollectionType`, `SerialComponentType`, `ContributorRole`, `ContributorGender`,
   `NumberingType`).

3. **`docs/reference/generated/CSL_JSON_MAPPING.md`** (generated). Same generator
   renders `type-map.json`'s `csl_type_map` array to a markdown table. Cross-link
   `docs/specs/CSL_TYPE_CONVERSION_CONTRACT.md` for full rationale.

4. **`docs/reference/BIBLATEX_MAPPING.md`** (fully generated, replaces the
   stale-notice version). Same generator renders `type-map.json`'s
   `biblatex_entry_types` and `biblatex_fields` arrays into the entry-type table
   and field table (with an explicit "not yet mapped" section for `Unmapped`
   rows -- this *is* the csl26-11h2 gap-analysis deliverable).

5. **`docs/reference/NATIVE_FORMAT.md`** (worked examples, test-backed). One
   worked native-YAML example per structural class plus two flat classes.
   Examples live as real files under `examples/data-model/*.yaml` (follow the
   existing convention: `examples/refs-rich.yaml`, `examples/chicago-bib.yaml`),
   inlined by the generator -- not pasted prose. Add a round-trip test in
   `citum-refs` that deserializes each into an `InputReference` and asserts the
   serialization round-trips, so a stale example fails CI.
